# Delicious-PPT

可配置的 PPT 制作与改稿 Skill，适用于课堂授课、工作汇报、项目提案、学术答辩、培训分享与阅读型演示文稿。**先充分访谈、达到约99%的需求理解并确认制作方案，再开工；每页图片背景、逐段动画安排、指定字体和背景融合必须执行。**

当前版本 **1.0.0**。从 [Releases 下载独立 Skill 与完整示例](https://github.com/Delicious-Cao/Delicious-PPT/releases/tag/v1.0.0)，或阅读 [安装与使用](docs/QUICKSTART.md)、[运行环境与兼容性](docs/RUNTIME.md)、[更新记录](CHANGELOG.md)。

## 强制字体、背景与文字动画

| 项目 | 强制要求 |
| --- | --- |
| 中文标题 | 小标宋 |
| 中文正文及说明 | 仿宋，明确不加粗 |
| 数字、拉丁字母与英文 | Times New Roman（新罗马体），包括页码、图表及表格中的文字 |
| 图片背景 | 融入整页，与文字重合的区域局部淡化，文字保持清晰不透明 |
| 制作过程标签 | 清理页面及演讲者备注中自动添加的“AI生成场景示意”“AI配图”等字样 |

以上要求同时适用于两个版本，不重新询问是否省略。模板、工具或字体有冲突时说明具体缺项，不能静默换字体或去掉背景。本仓库不捆绑字体文件。只有使用者后续明确改变对应要求时才调整。

强制保留并执行以下文字动画原话：

> 每段文字出现必须要有动画效果，可以一起出现也可以一个一个出现，也可以没有动画等总体得符合此时场景的变化。

每段文字都要安排出现方式，可整组、逐项，或因具体场景静态显示；静态例外在内部记录理由，不能据此把整套一律设为无动画。动画和翻页效果须真实写入 PPTX。

## 先问哪些问题

先完整阅读消息、附件与已有对话，再围绕使用者的真实目标充分访谈。**问题不必简短，不机械限制每轮数量或轮数；必要时说明询问目的、选项差异与成品影响，分主题深入追问，直到关键需求清楚。** 支持选项、长篇自由回答与参考案例；已明确的信息不重复问。

| 可选项 | 根据本次任务确认的内容 |
| --- | --- |
| 使用场景 | 用于授课、汇报、答辩、提案还是分享？面向谁，希望对方理解或决定什么？ |
| 演示方式与时长 | 现场讲述、自动播放还是独立阅读？讲多久，是否包括问答和互动？阅读型文件可以不设时长。 |
| 内容详略 | 精简要点、均衡解释还是详细可读？需要哪些关键内容，有没有页数限制？ |
| 视觉与构图 | 正式、简洁、活泼或其他气质？有品牌色或模板吗？背景偏完整场景还是图文留白？ |
| 动画编排与放映 | 文字以整组还是逐项出现为主？手动还是自动推进？使用什么放映软件？ |
| 资料与交付 | 使用什么语言、允许哪些资料来源？需要 PPTX、PDF、备注或讲稿？保存到哪里？ |

按具体任务深入了解目标、必须保留项、优先级、参考与排斥项、展示环境和交付条件。记录每项是已明确、已授权助手决定、不适用还是待确认；“你决定”只授权对应项目，不能自动补齐其他未知项。

## 约99%理解后才开工

“99%”落实为可检查的开工条件：所有关键需求已明确或明确授权，必要资料齐全，冲突已解决，没有会导致大幅返工的未知项；不声称测得精确的理解率。

开工前提供《制作需求确认单》，完整复述目标、受众、内容范围、结构方向、时长口径、详略、风格、强制要求、来源边界、放映与交付条件，以及已委托助手决定的项目，让使用者纠正并确认开工。对同一完整方案已有明确确认与授权时无需重复确认。

未达门槛或等待必要回答时，只阅读整理现有资料和检查工具，不开始正式内容编写、版式设计、批量生成或搜索背景、动画实现和 PPTX 制作。完整访谈方法、提问示例及确认单内容见各版本的 `references/requirements-intake.md`。

**38–40 分钟、PPT 展示约 80%、积极色调与保存桌面仍是可选参数；每页图片背景、逐段动画安排、指定字体和整页融合淡化则为强制要求。** 原始偏好保留为可主动选用的“课堂评审预设”，详见各版本的 `references/requirements-intake.md`。本仓库最初对话中的偏好不会自动套用到后续所有使用者。

## 持续保留的质量标准

- 逻辑连贯、信息可读、符合受众和展示条件，不靠缩小文字硬塞内容。
- 按主题核验事实、日期、数据口径与图片使用条件；内容资料边界与强制背景获取方式分开处理，有明确冲突先澄清。
- 现场讲述版按已确认的时长安排节奏；阅读版优先保证独立可理解，不强加演讲时长。
- 每页必须嵌入指定来源的图片背景，每段必须有出现安排；逐段动画、静态例外和翻页效果以实际文件验收。
- 必须形成含图片背景与真实动画的可编辑 PPTX，PDF 作为附加静态版；不声称完成了未实际执行的保存、排练或动态检查。

## 使用方法

### 支持 Skill 目录的工具

下载或克隆仓库，将选定的整个 Skill 文件夹放入宿主支持的技能目录，保留 `SKILL.md` 与 `references/` 的相对位置。例如，Codex 默认个人技能目录为 `~/.codex/skills/`；ChatGPT 版另附兼容宿主可识别的 `agents/openai.yaml`。

### 普通对话

上传所选版本的 `SKILL.md`、该目录的参考文件，以及本次需要使用的资料。只接受文本的界面可以粘贴对应文件内容。宿主需提供本次任务所需的文档读取、检索、制图与导出工具，Skill 本身不会新增这些能力。

通用提示：

```text
请使用 Delicious-PPT 的 ChatGPT 版帮我制作 PPT。
先充分阅读资料并深入询问我的目标、受众、时长、内容范围、详略、
风格、展示环境和交付要求，问题不必简短，可以多轮追问。
达到约99%的需求理解后，向我复述制作需求确认单，确认后再开工。
强制背景、字体和逐段出现要求保留执行。
```

也可以直接提供完整需求，减少询问：

```text
使用 Delicious-PPT 的 DeepSeek 版，把这份材料做成 10 分钟的项目汇报，
面向管理层，以结论和决策建议为主，风格正式简洁。
自行联网搜索每页背景，整页融合、文字区淡化；逐段淡入并设置翻页过渡，
使用小标宋标题、仿宋正文不加粗、Times New Roman 数字字母，输出 PPTX 和 PDF，
保存到我指定的文件夹。不需要讲稿，其余细节你决定。
```

默认只选一个版本，避免同时启用不同图片策略。
