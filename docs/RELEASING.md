# 维护与发布

## 发布前

1. 更新 `VERSION`、两个 Skill 的 `metadata.version` 与 CHANGELOG，说明已验证范围和已知限制。
2. 运行 `python maintenance/sync_references.py --check`，校验共用参考同步与 Markdown 相对链接。
3. 如修改了示例，审阅原始材料、素材来源、字体、可编辑性、每页背景、文字动画与翻页，并刷新逐页预览和动画视频。
4. 准备干净的发布包：两个独立 Skill ZIP、完整仓库 ZIP，以及示例 ZIP。独立包保留整个技能目录和许可。
5. 为每个发布包生成 `SHA256SUMS.txt`，检查 ZIP 可解压，确保不含凭据、私有资料、字体文件或工作目录。

## 创建发布

在已审阅的提交上创建 `v版本号` Tag 和 GitHub Release。发布正文包括变更、下载包用途、兼容说明和未验证项；将 ZIP 与 SHA-256 校验文件作为附件。

不要移动已经公开的版本 Tag 或覆盖同名发行附件来隐藏内容变化。修正已发布内容时发布新版本，并解释修正范围。

## 发布后

核实 Release 页面公开可访问，Tag 指向预期提交，附件完整、大小与散列相符。抽查下载包中的两个 Skill 入口、参考文件和示例入口。

保留问题模板，按报告区分模型理解、宿主工具、字体、动画和文件导出的问题。只有完成了相应测试，才将兼容矩阵从“未验证”改为“已验证”。
